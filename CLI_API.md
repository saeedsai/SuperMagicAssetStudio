# SuperMagic Asset Studio — PowerShell Agent CLI API

Created by **Saeed**  
Contact: **saeedmsalehi1990@gmail.com**

## What it does

`SuperMagicAssetStudio.ps1` is a terminal API for autonomous AI agents and scripts. It wraps `agent-cli.mjs`, a Node.js 20+ headless editing/rendering engine (no npm installation necessary). It works directly with the **same `FootballSpriteStudio` JSON** that the HTML editor loads and saves. The CLI supports eight directions, all four character-structure modes, custom part schemas, image import, layer order and visibility, transforms/crops, RGB/HSL-style color adjustment, grid/rulers, reference overlays, animation frames and linked clips, undo/redo, validation, and PNG/GIF/sprite-sheet/turntable exports.

Unlike the in-browser console API, the PowerShell CLI **does not need the HTML editor running**. The editor can subsequently load any project generated by the CLI.

## Requirements

- PowerShell 7+ (`pwsh`) or Windows PowerShell 5.1 (`powershell.exe`).
- Node.js 20 or later in `PATH` (https://nodejs.org).
- No npm modules or Python packages required.
- For CLI rasterization, **PNG** source images are supported. If you have JPEG/WebP input, convert it to PNG first. Rendering approximates browser color filters and uses nearest-neighbor pixel sampling; it may differ slightly from the canvas output.

## PowerShell usage

From the extracted folder:

```powershell
pwsh -NoProfile -File ./SuperMagicAssetStudio.ps1 -Help
pwsh -NoProfile -File ./SuperMagicAssetStudio.ps1 -ListOperations
pwsh -NoProfile -File ./SuperMagicAssetStudio.ps1 -Project ./my-player.json -Operation summary
pwsh -NoProfile -File ./SuperMagicAssetStudio.ps1 -Project ./my-player.json -Operation review
pwsh -NoProfile -File ./SuperMagicAssetStudio.ps1 -Project ./my-player.json -CommandFile ./cli-example-commands.json
```

Use an inline command in PowerShell:

```powershell
$cmd = @{commands=@(@{op='setMode'; mode='custom'},@{op='setProjectName';name='Alex'})} | ConvertTo-Json -Depth 20 -Compress
pwsh -NoProfile -File ./SuperMagicAssetStudio.ps1 -Project ./alex.json -CommandJson $cmd
```

Direct Node.js use is also supported:

```shell
node agent-cli.mjs --project ./my-player.json --command-file ./cli-example-commands.json
node agent-cli.mjs --project ./my-player.json --op review
node agent-cli.mjs --list-ops
```

Output is UTF-8 JSON with `ok`, `project`, `saved`, `results`, and `validation`; failures write JSON to standard error with exit code `1`. Agent code can parse the JSON. The `--dry-run` flag evaluates transformations without saving the project or exports. `--output` allows writing to another project path. Every edit runs against an in-memory project and is committed by an atomic file replacement after successful command execution.

## The command format

```json
{
  "commands": [
    {"op": "setProjectName", "name": "Alex"},
    {"op": "setView", "view": "front"},
    {"op": "setGrid", "enabled": true, "rulers": true, "snap": false, "size": 32},
    {"op": "review"}
  ]
}
```

This is a **structured command protocol**, not a natural-language interface. See `cli-command-schema.json` for the machine-readable list of operations and base request schema.

### Project and editor configuration

| Operation | Important parameters |
|---|---|
| `createProject` | `name`, `mode`, `assetStorage` |
| `setProjectName` | `name` |
| `setCanvas` | `width`, `height` (1–4096) |
| `setMode` | `mode`: `fullBody`, `bodyHead`, `standard`, `custom` |
| `setImageStorage` | `mode`: `bundled` or `external` |
| `setView` | `view` (one of eight IDs below) |
| `rotateView` | `steps` (+1 / -1 / etc.); 45° per step |
| `setAnimation` | `animation` |
| `setFrame` | `frame` |
| `setEditor` | `changes`: serializable editor settings including `reference`, `grid`, `rulers`, `snap`, `gridSize` |
| `setGrid` | `enabled`, `rulers`, `snap`, `size` |
| `setReference` | `view`, `animation`, `frame`, `alpha` (default 0.3), `enabled` |
| `clearReference` | no parameters |
| `setDefault` | `view`, `category`, `transform` — default placement for future layers |
| `undo`, `redo` | persistent per-project history (up to 10 command batches) |

Valid views: `front`, `threeQuarterFrontLeft`, `left`, `threeQuarterBackLeft`, `back`, `threeQuarterBackRight`, `right`, `threeQuarterFrontRight`.

### Modular character structure

| Operation | Important parameters |
|---|---|
| `setPartsDefinition` | `base` (e.g. `standard`), optional `parts` array; omitted parts copies base |
| `addCustomPart` | `id`, `name`, `group`, optional `default` |
| `updatePart` | `id`, optional `name`, `group`, `default` |
| `removePart` | `id` |
| `reorderPart` | `id`, `toIndex` |
| `exportPartsDefinition` | `mode`, optional `path` to write JSON |
| `listParts` | no parameters |

### Images and layers

| Operation | Important parameters |
|---|---|
| `addAsset` | `id`, `file` (PNG path), optional `name`; alternatively `src` data URL or external `fileRef`, `width`, `height` |
| `replaceAsset` | `id`, `file` / `src` |
| `removeAsset` | `id` (only if unused) |
| `addLayer` | `id`, `assetId`, `category`, `name`, `view`, `animation`, `frame`, `crop`, `transform`, `color`, `visible`, `locked`, `order` |
| `setLayer` | `match`, `scope`, `changes` (transform, crop, color, visibility, etc.) |
| `setColor` | `match`, `color` |
| `setCrop` | `match`, `crop`: `x`, `y`, `w`, `h` |
| `setTransform` | `match`, `transform` |
| `setVisibility` | `match`, `visible` |
| `mirrorLayer` | `match`, optional `reflectPosition` |
| `lockLayer` | `match`, `locked` |
| `autoFit` | `match` (heuristic placement; manual adjustment recommended) |
| `moveLayer` | `match`, `direction`: `front`, `back`, `up`, `down` |
| `deleteLayer` | `match` |
| `cloneLayer` | `match`, optional `toView`, `toAnimation`, `toFrame`, `mirror` |
| `reuseView` | `source`, `view`, `mirror`, `replace`, optional `animation`, `category` |
| `importManifest` | `manifest` object or local JSON file with `items` array |

Layer matching example: `"match":{"category":"head"}` or `"match":{"id":"head_layer"}` or `"match":{"nameContains":"left"}`. Scopes: `currentFrame`, `currentAnimationCurrentView`, `allCurrentView`, `all`. If omitted, scope defaults to `currentFrame` using the CLI cursor. For layers in other views, provide `view`, `animation`, `frame` or change the cursor using `setView`/`setAnimation`/`setFrame`.

Example of independent RGB and tint control:

```json
{
  "commands": [
    {"op":"setView","view":"front"},
    {"op":"setColor","match":{"category":"head"},"color":{"red":120,"green":95,"blue":85,"brightness":108,"hue":0,"sepia":15,"saturate":100,"contrast":100,"tintHex":"#cc9966","tintAmount":20}},
    {"op":"setTransform","match":{"category":"head"},"transform":{"x":384,"y":185,"scaleX":0.4,"scaleY":0.4,"rotationDeg":5,"flipX":false}},
    {"op":"setCrop","match":{"category":"head"},"crop":{"x":10,"y":0,"w":490,"h":500}}
  ]
}
```

| Operation | Important parameters |
|---|---|
| `createAnimation` | `id`, `name`, `fps`, `frames` (names or descriptors) |
| `renameAnimation` | `animation`, `name` |
| `setFPS` | `animation`, `fps` |
| `deleteAnimation` | `animation` |
| `addFrame` | `animation`, `id`, `name`, optional `reuse` source |
| `duplicateFrame` | `animation`, `sourceFrame`, `id`, `link` |

### Rendering and export

These actions do not need an open browser:

| Operation | Parameters |
|---|---|
| `renderPNG` | `view`, `animation`, `frame`, `scale`, `path`, `hiddenCategories` |
| `renderSpriteSheet` | `view`, `animation`, `columns`, `scale`, `path` |
| `renderGIF` | `view`, `animation`, `scale`, `path` |
| `renderTurntable` | `animation`, `scale`, `path` (all eight views) |

Rendering uses **transparent RGBA output** for PNG and a transparent indexed palette for GIF. GIF uses 256 colors. Source pixels are sampled nearest-neighbor for game-art sharpness. Maximum PNG frame size is 8 MP and sprite sheet size is 12 MP. Defaults to 480px maximum dimension for GIFs unless a `scale` is specified.

### Inspection

`summary`, `review`, `listAssets`, `listParts`, `listLayers`, `getProject` return structured results in `results[].value`. `review` identifies missing external images, broken links, invalid crops, and unknown layer asset IDs.

## External versus bundled images

- `external` mode copies imported PNGs into the project's `assets/` directory and saves only `fileRef` paths. Move the project together with `assets/`.
- `bundled` mode embeds the source PNG as a base64 data URL in `assets[...].src`.
- Switch with `{"op":"setImageStorage","mode":"bundled"}` or `external`.
- The browser editor can open either JSON format. External images may need resolution in the editor's `Resolve external images` button if opened using `file://` (browsers restrict direct disk reads).

## Security and limits

- Commands use a strict operation switch. **No JavaScript eval or shell code is run from JSON**.
- The CLI writes only to explicitly selected project, export, or referenced image paths. An AI agent should run it in a controlled workspace.
- The CLI makes no internet requests.
- This is a headless **data API and raster renderer**. Interactive UI-only features such as dragging handles or playing a preview are represented by equivalent numeric transforms, frame selection, and animation data, rather than literally driving a mouse.
- Browser canvas blending, filter interpolation, and font rendering can differ slightly from the CLI's PNG/GIF renderer.
- PowerShell itself was not available in the build environment; the underlying Node entry point and image exports were tested end to end.


### `autoResizeMatching` (v5.3)

```json
{
  "op":"autoResizeMatching",
  "sourceMatch":{"category":"head"},
  "scope":"all",
  "matchBy":"category",
  "method":"sourceScale"
}
```

Scopes: `currentFrame`, `currentAnimation` (all eight views), `currentView` (all animations), `all` (all views and animations).
Methods: `sourceScale` (same PNG-relative scale), `renderedHeight`, `renderedWidth`. Original PNG resolution remains unchanged.


## Additional image tool commands (v5.4)

`splitImageAuto`, `splitImageManual` and `removeBackground` operate on PNG files and return file paths plus a manifest. See **IMAGE_TOOLS_API.md** for complete examples, parameters and caveats. They can be issued in the same commands array as regular asset-project operations. Example:

```json
{"commands":[{"op":"splitImageAuto","source":"./sheet.png","outputDir":"./extracted","minPixels":1000,"alphaThreshold":25,"padding":3,"assignments":[{"view":"front","category":"head"}],"importToProject":true},{"op":"review"}]}
```

When `importToProject:true`, files are also registered as assets and layers and saved through the existing bundled/external JSON pipeline. The PowerShell wrapper executes the same Node CLI; no PowerShell-specific image-processing library is required.
